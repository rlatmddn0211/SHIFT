# SHIFT 공모전 작품 소개 초안

이 문서는 공식 접수양식의 작품 소개 항목에 옮겨 쓸 본문 초안이다. 참가신청서와 참가자 전원의 동의·서명을 대체하지 않는다. 기획 기준은 [전체 기획안](PLAN.md), 범위 확정 내역은 [결정 기록](DECISIONS.md)을 따른다.

1차 제출은 기획서, 화면 시안과 클릭형 프로토타입 시연 영상으로 준비한다. 아래에서 설명하는 실제 계정·SDK 연동은 2차 PT까지 구현·검증할 목표이며, 현재 구현 완료를 뜻하지 않는다. 실증 규모와 팀별 개발 일정은 추가 답변 후 보완한다.

## 1 한 문장 소개

SHIFT는 배정받은 공용차에서 직원이 자신의 방문 업무와 개인 서비스를 이어 쓰고, 이용이 끝나면 개인 업무 세션을 정리하는 Pleos Connect 앱이다.

## 2 주목한 고객과 문제

첫 적용 대상으로 현대자동차 사내 공용차로 고객사를 방문하는 영업·외근 직원을 설정한다. 이들은 이용할 때마다 같은 차량을 배정받는다고 보장하기 어렵고, 방문 일정과 변경된 미팅 장소는 메일과 일정에, 이전 상담 내용은 노트에 나뉘어 있다. 차량 이용을 시작할 때 필요한 정보를 찾아 목적지를 다시 입력하고, 방문 후에는 상담 메모를 자신의 업무 도구에 옮겨야 한다.

공용차는 이용자가 계속 바뀐다는 점도 고려해야 한다. 개인 업무를 불러오는 편의뿐 아니라, 이용을 마쳤을 때 다음 직원이 이전 직원의 업무 정보에 접근하지 못하도록 세션을 끝내는 절차가 필요하다.

SHIFT는 방문 준비와 기록을 하나의 흐름으로 연결한다. 준비는 휴대폰에서 하고, 차량에서는 현재 방문에 필요한 정보를 확인하며, 방문 후 메모는 기존 업무 도구에 저장한다. 이미 차량을 배정받았다는 상태에서 시작하고 사내 차량 관리 기능은 확장으로 남긴다. 개인 업무 내용은 회사 관리자에게 공개하지 않는다.

반복 입력 시간과 업무 정리 부담의 개선 정도는 아직 실측하지 않았다. 시제품으로 기존 이용 방식과 비교해 검증한다.

## 3 제공할 기능과 차량에서의 가치

### 탑승할 때 내 업무 환경 연결

직원은 회사 초대 링크를 열고 등록된 회사의 Microsoft 조직 계정으로 가입한다. 기존 회사 절차로 배정받은 차량에서 SHIFT를 실행하고, 휴대폰으로 QR을 확인해 현재 차량에 업무 환경을 연결할 것을 승인한다. 이 흐름을 위한 회사·차량 식별정보는 시험 환경에 사전 설정한다.

처음에는 Microsoft 365와 OneNote의 사용 권한을 각각 승인한다. 이후 탑승에서는 이미 연동한 서비스를 현재 차량의 이용 세션에 연결하는 경험을 제공한다. 다음 탑승을 위해 서비스 연결 상태와 선택한 노트 등 최소 설정을 계정에 보관하고, 사용자가 언제든 연결 해제할 수 있게 한다. 공조·풍량·조명의 고정값을 복원하는 기능은 이번 출품 범위에서 제외한다.

업무 연동은 직원이 선택한다. 메일·일정·OneNote의 권한을 부여하지 않은 직원도 인증과 세션 관리를 사용할 수 있으며, 각 업무 기능은 해당 권한을 받은 뒤 활성화한다.

### 방문 업무와 내비게이션 연결

오늘 일정과 최근 7일의 관련 메일, Outlook 중요 표시·미확인 메일을 확인해 방문 준비에 필요한 정보를 요약한다. 장소를 제안할 때는 일정 또는 메일의 근거를 함께 표시한다. 장소가 불분명하거나 변경 가능성이 있으면 후보를 보여주고, 직원이 확인한 목적지를 NaviHelper SDK로 차량 내비게이션에 전달한다.

방문 장소를 확인하고 차량의 경로 안내로 이어지는 과정의 재입력을 줄인다. 요약 오류가 바로 잘못된 경로 실행으로 이어지지 않도록 사용자 확인을 거친다.

### 선택한 노트와 음성 메모

휴대폰에서 미리 선택한 OneNote 노트를 차량에서 확인하고, 새 메모를 음성으로 입력해 내용을 확인한 뒤 개인 OneNote의 전용 섹션에 저장한다. 기존 노트의 수정 기능은 제외한다. 상담 전 참고한 정보와 상담 후 기록이 사용자의 기존 업무 도구에 남도록 한다.

### YouTube Music 실제 이용

음악 서비스는 YouTube Music을 대상으로 한다. 개인 목록 조회와 차량 재생·조작을 제공하는 공식 경로를 먼저 검증한다. 해당 경로를 확보하지 못하면 휴대폰 공식 앱에서 재생하고 차량 오디오로 전달하는 방식도 허용한다.

휴대폰 재생 경로를 이용할 때 SHIFT 자체의 재생목록 조회·조작까지 구현했다고 표현하지 않는다. QR 이용 승인과 휴대폰의 차량 오디오 연결도 별도 절차로 안내한다.

### 개인 세션 종료와 다음 직원으로의 전환

이용 종료 시 차량의 SHIFT 개인 세션과 앱 내 개인 데이터를 정리한다. 다음 직원은 새로운 인증으로 자신의 업무 환경을 연결한다. 개인 메일·노트·음악 내용은 회사 관리자에게 공개하지 않는다.

수동 종료와 휴대폰 원격 종료를 제공하고, 일정 시간 비활동 후 개인 세션을 잠근다. 잠금 시간과 비활동 판정은 시험 후 정한다. 차량 제어나 기존 내비게이션은 중단하지 않는다. 정리 범위는 SHIFT가 관리하는 데이터이며 차량 전체와 다른 앱의 모든 이력 삭제를 의미하지 않는다.

### 주행 상태에 맞춘 이용

차량 인증, 업무 준비, 긴 원문 조회, 노트 선택과 이용 종료는 우선 주차 상태에서 설계한다. 주행 중에는 앱 카테고리와 플랫폼이 허용하는 기능만 제공한다. 차량 내비게이션, 음성 입출력과 이용자 교체 흐름이 차량 환경에서의 가치를 만든다.

## 4 대표 이용 장면

다음은 기능을 설명하기 위한 가상 시험 시나리오다. 고객 확보나 실제 도입 실적으로 제시하지 않는다.

최초 준비로 직원 A가 회사 계정과 필요한 업무 서비스를 연결하고 가져올 노트를 선택한다. 이후의 핵심 흐름은 다음 여섯 단계다.

1. **배정받은 차량 탑승:** 기존 회사 절차로 배정받은 공용차에 탑승한다.
2. **SHIFT 인증:** 주차된 차량에서 SHIFT를 켜고 휴대폰 QR 승인으로 자신의 업무 환경을 연결한다.
3. **내 방문 업무 확인:** 오늘 일정, 관련·중요 메일과 선택한 OneNote 노트로 방문을 준비한다.
4. **목적지 전달:** 장소 변경 메일의 근거와 주소를 확인하고 차량 내비게이션에 전달한다.
5. **방문 후 메모:** 방문을 마친 뒤 주차 상태에서 음성 메모를 작성하고 내용을 확인해 OneNote에 저장한다.
6. **개인 세션 종료:** 차량의 개인 업무 연결과 데이터를 정리한다.

이후 직원 B가 같은 차량에서 인증해 B의 환경으로 전환되는 장면을 보여준다. B가 A의 개인 정보에 접근할 수 없어야 한다. 음악은 검증한 YouTube Music 이용 경로를 보조 기능으로 제공한다. 관리자 등록과 예약·취소·차량 반납은 이번 시연 범위에 포함하지 않는다.

## 5 구현과 검증 계획

차량은 Kotlin·Jetpack Compose의 Pleos Connect Android 앱으로, 휴대폰은 TypeScript·React·Next.js 모바일 웹으로 구성한다. API는 같은 Next.js 프로젝트의 Route Handlers에서 제공하고 PostgreSQL에 최소 설정과 세션 상태를 저장한다. Microsoft 인증은 공식 MSAL Node와 Microsoft Graph를 사용한다. 호환 버전과 배포 환경은 초기 빌드·인증 검증 뒤 고정한다.

| 연결 대상 | 구현할 역할 | 확인할 조건 |
| --- | --- | --- |
| Microsoft Graph | Microsoft 365 인증, 일정과 메일 조회, OneNote 조회와 새 페이지 저장 | 시험 계정의 서비스 이용 가능 여부, 조직 동의, 위임 권한 |
| NaviHelper SDK | 직원이 확인한 목적지를 차량 내비게이션에 전달 | 주소·좌표 확인, 경로 요청 결과와 오류 처리 |
| SpeechToText SDK | 새 메모의 음성 입력을 텍스트로 변환 | 에뮬레이터 지원 모드와 실제 인식 결과 |
| 주행 규제 API | 차량 상태에 맞춰 화면과 입력을 제한 | 앱 카테고리, CarUxRestrictions 및 실제 동작 |
| YouTube Music | 실제 음악 이용 연결 | 차량 직접 연동의 공식 지원 또는 휴대폰 공식 앱과 차량 오디오 경로 |

공개된 SDK·API 범위에서 개발하며 미공개 SDK나 Pleos LLM SDK 제공을 전제하지 않는다. 차량 마이크의 외부 음성 인식 서비스 전송을 전제하지 않고 공식 SpeechToText SDK를 사용한다. [공식 개발 범위](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)

11월 15일의 1차에는 핵심 흐름을 설명하는 시안과 클릭형 시연 영상을 제출한다. 차량은 짙은 업무 도구 화면, 휴대폰은 밝고 간결한 화면으로 디자인하고 PC에 나란히 띄워 녹화한다. 이후 실제 계정과 SDK를 연결해 12월 3~4일 PT 전 Pleos 에뮬레이터의 실제 동작을 검증한다. [제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission), [심사 안내](https://appdevchallenge.auto-hmg.io/guide/judging-awards)

기술 검증은 Pleos 앱 실행과 Microsoft 365 권한 확인에서 시작해 QR 세션, 목적지 전달, OneNote 조회·저장과 음악 이용 경로를 연결하는 순서로 진행한다. 마지막으로 A/B 전환과 종료 누락·통신 단절을 확인한다. 세부 일정과 개발 분담은 아직 미정이다.

AI 요약 방식, 주소·좌표 검색 수단과 오류 시 재시도 정책은 실제 개발 착수 때 확정한다. 비활동 잠금 시간, 세션·시험 기록 보관 기간과 실증 규모는 시험·실증 협의 후 정한다.

방문 준비 시간의 기존 방식 대비 비교, 실제 OneNote 저장 결과, A/B 전환 후 이전 정보 접근 차단을 모두 자체 시험한다. 가능하면 다른 회사의 공용차 외근 직원·운영자에게도 실제 불편을 인터뷰한다. 타사 인터뷰 결과와 현대차 사내 실증은 구분하며, 아직 측정하지 않은 효과를 수치 성과로 제시하지 않는다.

## 6 제공 가치와 확장

직원에게는 방문 업무 준비와 차량 내비게이션 사이의 재입력, 방문 후 노트 정리와 개인 업무 세션 정리 부담을 줄이는 가치를 제공한다. 사내 도입 관점에서는 공용차에서도 기존 업무 도구를 이어 쓰고 직원 교대 시 개인 정보를 분리할 수 있는지를 검증한다.

독립적인 구독 사업 대신 현대자동차가 사내 공용차 운영에 활용할 수 있는 내부 서비스로 제안한다. 우선 공용차 이용 조직에서 실증하고, 실사용 효과와 운영 적합성을 확인한 뒤 사내 적용 범위를 넓힌다. 실증 대상 조직과 인원·차량 대수는 아직 미정이며, 실제 도입이 확정된 제안은 아니다.

사업성 검증에서는 등록 계정 수와 실제 활성 이용자를 구분한다. 월간 활성 이용자는 실제 차량 업무 세션을 사용한 직원 수로 측정하고, 재이용은 업무상 공용차를 다시 사용할 기회가 있었던 직원의 반복 이용을 함께 확인한다. 목표 MAU와 유지율을 검증 없이 실적으로 제시하지 않는다.

기본 흐름을 검증한 뒤 외부 기업의 공용차로 확대를 검토한다. 차량 예약·배정·대여·반납과 관련 관리자 기능은 향후 확장에 포함한다. 기업별 업무 도구와 운영 방식에 맞춰 연동 범위를 조정하며, 현대자동차의 실제 사내 인증·업무 시스템 연계는 별도 협의와 검증이 필요하다.

## 7 첨부할 참고자료

1차 제출 시 화면 시안, 클릭형 프로토타입 시연 영상과 실제 제출에 사용할 저장소 또는 자료 링크를 기재한다. 현재는 자료 제작과 공개 범위를 정하기 전이므로, 존재하지 않는 URL이나 실제 동작하지 않는 APK를 제출 자료로 표시하지 않는다.

공식 접수양식의 참가자 정보와 전원 동의·서명은 팀에서 별도로 작성한다. 작품 소개와 시연 화면에는 참가자의 실명, 연락처, 실제 업무 메일이나 계정 토큰을 넣지 않는다. [공식 접수양식](https://appdevchallenge.auto-hmg.io/downloads/contest-application-consent.docx)
