# SHIFT 공모전 작품 소개 초안

2026년 11월 15일 GitHub fetch 기준. 확정 기획 v1.2와 개발 브랜치 `codex/pleos-screen-dev`의 `de142f6df8d7c1233e410d933dca56fd7fab82f5`를 반영했다. 아래 1~8번을 공식 Word 양식에 넣는다. 공개 웹 시연과 실제 Pleos 앱·연동 서버의 검증 범위를 구분한다.

## 1 앱 한 줄 소개

SHIFT는 공용차의 Pleos Connect에서 개인별 좌석 설정과 방문 업무를 불러오고, 내비게이션·메모를 휴대폰과 이어 쓰며, 교대 시 개인 세션을 정리하는 앱입니다.

## 2 기획 배경

회사 공용차로 고객사를 방문하는 영업·외근 직원은 탑승할 때마다 업무 환경을 다시 준비합니다. 방문 시간과 장소는 일정·메일에, 상담 내용은 노트에 나뉘어 있습니다. 미팅 장소가 바뀌면 휴대폰에서 관련 내용을 찾아 차량 내비게이션에 주소를 다시 입력하고, 방문 후 메모를 업무 도구로 옮겨야 합니다. 차량을 바꿔 타면 좌석 높이와 앞뒤 위치도 다시 맞춥니다. 여러 직원이 같은 차를 이용하므로 이전 이용자의 업무 정보 접근을 끝내는 과정도 필요합니다.

SHIFT는 회사의 기존 절차로 차량을 배정받은 직원이 휴대폰과 차량에서 자신의 업무를 이어서 처리하도록 돕습니다. 휴대폰 모바일 웹에서 연결한 업무 계정과 개인 프로필을 차량의 SHIFT 세션에 불러와 출발 전 방문 업무를 확인하고 목적지를 전달하며, 방문 후 메모를 남깁니다. 이용을 마치면 해당 차량의 개인 세션을 종료합니다. 다음 직원은 자신의 계정으로 새 세션을 시작합니다.

## 3 앱 주요 기능 및 차량 특화 요소

### 휴대폰에서 준비하고 차량에서 QR·PIN 인증

별도 SHIFT 휴대폰 앱 설치 없이 모바일 웹에서 업무 계정, 차량에 표시할 노트와 브리핑 항목, 좌석 프로필을 준비합니다. 차량 QR을 열고 일회용 PIN으로 승인하면 현재 탑승한 차량에 자신의 업무 환경이 열립니다. 새 직원의 인증이 완료되면 이전 차량 세션을 만료시킵니다.

### 원본 근거를 확인하는 방문 업무와 목적지 전달

오늘 방문 일정과 관련 메일을 함께 보여주고 시간·장소 변경을 짧게 브리핑합니다. 직원은 원본 일정·메일과 주소 후보를 확인한 뒤 Pleos 기본 내비게이션에 목적지를 전달합니다. 원문 확인과 내비게이션 입력을 연결해 출발 전 반복 작업을 줄입니다. 장소가 모호하거나 전달이 실패하면 확인·재시도 화면을 제공합니다.

### 휴대폰과 차량에서 이어 쓰는 업무 메모

휴대폰에서 작성한 방문 메모를 주차 상태의 차량에서 조회하고, 방문 후 차량에서 음성으로 작성한 메모는 인식 결과를 확인해 저장합니다. 저장한 내용은 같은 직원의 휴대폰에서도 확인합니다. Microsoft 365 연결 시에는 선택한 OneNote 노트를 조회하고 새 메모를 전용 섹션에 저장하는 방식으로 완성할 계획입니다. 현재 확인한 저장·조회는 시연 서버의 사용자별 데이터이며 실제 OneNote 저장 시험은 남아 있습니다.

### 개인별 좌석 높이·앞뒤 위치

운전석 높이와 앞뒤 위치를 개인 프로필로 준비하고 주차 상태에서 사용자 확인 후 차량이 지원하는 범위 안에서 적용합니다. 차종별 범위와 실제 위치 응답을 확인하며, 응답이 불확실하면 이동을 중단합니다. 에뮬레이터에서 조회와 이동·정지 명령을 시험했으며 목표 위치 도달과 실차 적용은 추가 검증 대상입니다. 공조·조명은 이번 범위에서 제외합니다.

### 음악 이어 듣기와 개인 세션 종료

음악은 휴대폰 공식 음악 앱에서 재생하고 차량 오디오로 이어 듣는 경로로 검증합니다. SHIFT는 연결 안내와 Pleos Bluetooth 설정 진입을 제공하며, 실제 페어링과 스피커 재생은 실기기 시험 대상입니다. SHIFT 자체 재생목록 조회·제어는 포함하지 않습니다.

로그아웃 QR을 휴대폰에서 승인하면 해당 차량의 SHIFT 세션과 앱이 관리하는 개인 화면·데이터를 정리합니다. 원본 메일·일정과 저장한 메모는 사용자의 서비스에 유지합니다. 회사별 차량 등록·권한·예약·반납·관리 기능은 후속 확장으로 두고, 이번 작품은 배정받은 차량 안에서 개인 업무 환경을 이어 쓰는 경험에 집중합니다.

## 4 주요 사용 시나리오

외근 직원 A는 휴대폰 모바일 웹에 업무 계정, 차량에서 볼 노트, 브리핑 항목과 좌석 프로필을 준비합니다. 업무 내용은 가상의 시연 예시입니다.

1. 배정받은 차량 탑승: A는 회사의 기존 절차로 배정받은 공용차에 탑승해 Pleos에서 SHIFT를 엽니다.
2. SHIFT 인증: 차량 QR을 열고 6자리 PIN으로 승인합니다. A의 업무 화면이 열리고 주차 상태에서 지원되는 좌석 프로필을 확인·적용합니다. 음악은 휴대폰 공식 앱과 차량 오디오 연결 경로로 이용합니다.
3. 방문 업무 확인: 오전 10시 30분 미팅 장소가 변경됐다는 브리핑을 듣고 변경 주소와 관련 메일의 근거를 확인합니다. 휴대폰에서 준비한 방문 메모도 함께 봅니다.
4. 목적지 전달: A가 확인한 장소를 Pleos 내비게이션에 전달합니다. SHIFT는 요청 결과를 표시하며 확인되지 않은 주소를 자동 실행하지 않습니다.
5. 방문 후 메모: 상담 후 주차 상태에서 ‘금요일까지 수정 견적을 보내기로 함’이라고 말하고 인식 내용을 확인해 저장합니다. 휴대폰에서도 같은 메모를 이어서 확인합니다.
6. 개인 세션 종료: A는 로그아웃 QR을 휴대폰에서 승인합니다. 다음 직원 B가 인증하면 B의 업무와 프로필을 엽니다. A가 종료를 잊은 경우에도 B의 인증 완료 시 A의 차량 세션은 만료됩니다.

주행 중에는 상세 업무 확인, 좌석 조작, 메모 입력 등 주차 전용 기능을 제한합니다. 세션 정리는 SHIFT가 관리하는 접근과 데이터에 적용하며 기존 내비게이션 안내나 다른 앱의 기록 전체를 삭제하지 않습니다.

## 5 개발 계획

### 개발 구성과 현재 진행 상황

차량은 Kotlin 기반 Pleos Connect Android 앱, 휴대폰은 React·TypeScript 모바일 웹, 서버는 Node.js·TypeScript로 구성했습니다. 시제품은 차량 세션을 서버 메모리에, 개인 설정과 시연 메모를 로컬 파일에 저장합니다. PostgreSQL과 HTTPS 운영 배포는 후속 구성입니다.

2026년 11월 15일 기준 저장소에는 서명 release APK, 차량·웹·서버 소스와 실행 안내가 있습니다. Pleos Connect Emulator 2.1.0, Android API 34, 전체 2560 × 1440 px / 160 dpi, 가로 앱 창 1682 × 1210 dp 및 Chrome 모바일 화면 390 × 844에서 수행한 실행 기록과 캡처를 첨부합니다.

현재 기록된 동작은 QR·PIN 로그인·로그아웃, A/B 교대와 이전 정보 접근 차단, 휴대폰 메모 작성 및 Pleos 조회, 차량에서 저장한 메모의 휴대폰 조회입니다. 공개 웹은 같은 경험을 예시 데이터로 체험하는 별도 클릭형 시연입니다.

시제품은 팀이 구성한 가상 사용자 A·B와 일정·메일·메모로 시험합니다. 실제 업무 서비스 연결은 동의한 Microsoft 365 개발용 계정에 시험 자료를 넣어 별도로 검증합니다. 현대자동차 사내 공용차는 적용 예시이며, 실제 사내 실증과 데이터 사용은 후속 협의 단계입니다.

### Pleos SDK와 외부 서비스 활용

- NaviHelper SDK: 공식 시험 목적지를 기본 내비에 전달하고 안내 중인 POI를 확인했습니다. 일반 방문 주소는 좌표와 Pleos POI ID를 확인한 뒤 전송하도록 검색·검증 경로를 보완합니다.
- TextToSpeech·SpeechToText SDK: 한국어 음성 합성의 완료 응답과 시험 PCM 음성의 인식 결과를 확인했습니다. 실제 차량 마이크 입력, 인식 오류 수정과 재시도를 추가 시험합니다. AI 제공자 연결은 동의·HTTPS 요청 코드를 구성했으며 실제 제공자 응답 검증은 남아 있습니다.
- Vehicle SDK: 좌석 높이·앞뒤 위치의 지원 범위와 현재 값을 조회하고 이동·정지 명령을 시험했습니다. 에뮬레이터 위치 응답 불일치 시 이동을 중단했으며 목표 위치 도달은 지원 환경에서 추가 확인합니다.
- Microsoft Graph: Outlook 일정·메일과 OneNote를 사용자 위임 권한으로 연결하는 코드를 구성했습니다. 실제 조직 계정의 동의와 조회·저장은 추가 시험이 필요합니다. 동의한 항목만 읽고 새 메모를 개인 OneNote 전용 섹션에 저장하도록 검증합니다.
- 주행 상태와 세션: 기어 상태와 CarUxRestrictions로 주차 전용 기능을 제한합니다. 새 탑승자 인증 후 도착한 이전 요청이 새 직원의 화면이나 저장 동작에 반영되지 않도록 검증합니다.
- 음악: Pleos Bluetooth 설정 진입은 확인했고 휴대폰 공식 앱의 실제 페어링·출력·지원 조작은 실기기에서 시험합니다.

### 다음 검증과 제출

1차에는 공식 기획서, 공개 클릭형 시연, 저장소와 release APK를 제시하고 시연 영상 링크를 추가합니다. 2차 PT 전에는 실제 Microsoft 365·OneNote와 차량 마이크 입력을 우선 검증하고 좌석·음악의 지원 조건을 확인합니다. 실제 서비스 연결과 시험 데이터 사용 범위를 시연 자료에 표시합니다.

핵심 검증은 기존 방식 대비 올바른 목적지 전달까지의 시간, 실제 OneNote 저장 성공률, A/B 전환 후 이전 직원 정보 접근 차단입니다. 역할 분담, 데이터 보유 기간과 실증 규모는 후속 확정합니다. 계정 연동은 [Microsoft Graph OneNote 안내](https://learn.microsoft.com/en-us/graph/integrate-with-onenote)를 따르고 좌석은 [Pleos Seat API](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/seat/entry)의 지원 범위를 확인합니다.

## 6 기대효과 및 발전 가능성

SHIFT를 현대자동차가 기업 공용차에 적용할 수 있는 서비스로 제안합니다. 외근 직원은 차량이 바뀌어도 업무와 착석 환경을 이어 쓰고 방문 주소 재입력과 상담 메모 정리 부담을 줄일 수 있습니다. 같은 차량의 다음 직원은 이전 이용자의 업무를 보지 않고 자신의 환경으로 시작합니다.

첫 도입 검토 대상은 공용차를 함께 쓰며 고객사를 반복 방문하는 영업·외근 조직입니다. 기존 차량 배정 절차와 함께 시험할 수 있어 예약 시스템 도입 없이 핵심 경험을 검증할 수 있습니다. 운영 부서와 소규모 실증을 협의하고 반복 이용 빈도와 이용 중단 원인을 확인한 뒤 적용 부서를 넓힙니다. 아직 실제 사내 실증이나 도입 실적은 없습니다.

예상 MAU는 실증 대상 직원 수와 월 1회 이상 이용하는 비율로 산정합니다. 4주 재이용률은 첫 이용 주의 직원 중 네 번째 주에 다시 이용한 비율로 측정합니다. 현재는 모집 규모와 데이터가 없어 수치 목표를 확정하지 않았으며 시제품 시험과 실증 협의 후 정합니다.

핵심 경험을 검증한 뒤 외부 기업 공용차로 확대하고 회사별 차량 등록·이용 권한·예약·관리 기능을 추가할 수 있습니다. 첫 작품의 가치는 차가 바뀌어도 이용자 자신의 업무를 이어 가고, 이용을 마치면 차량의 개인 세션을 정리하는 경험입니다.
