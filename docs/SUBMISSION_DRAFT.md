# SHIFT 공모전 작품 소개 초안

이 문서는 공식 접수양식의 작품 소개 본문이다. 기획 범위는 [전체 기획안](PLAN.md), 확정 사항과 미정 항목은 [결정 기록](DECISIONS.md)에서 관리한다.

## 1 한 문장 소개

SHIFT는 배정받은 공용차에 탄 직원이 현대차의 Pleos Connect 화면에서 방문 업무를 확인하고, 내비게이션으로 목적지를 보내고, 방문 후 메모를 남긴 뒤 개인 세션을 종료하는 앱이다.

## 2 주목한 고객과 문제

첫 적용 대상으로 현대자동차 사내 공용차로 고객사를 방문하는 영업·외근 직원을 설정한다. 직원은 출발 직전에 일정과 메일에서 변경된 방문지를 확인해 차량 내비에 다시 입력하고, 방문을 마친 뒤에는 상담 메모를 업무 도구에 옮긴다. 여러 직원이 같은 차량을 쓰는 환경에서는 개인 업무가 교대 후에도 차량 화면에 남을 수 있다.

SHIFT는 회사에서 차량을 배정받은 뒤 실제로 탑승하는 순간부터 이 문제를 다룬다. 현재 운전자의 방문 업무와 차량 내비, 방문 후 기록을 차량 화면에서 연결하고, 다음 직원이 차를 쓰기 전에 차량의 개인 세션을 정리한다.

## 3 제공할 기능과 차량에서의 가치

### 차량 화면에서 내 업무 시작

배정된 차량에 탑승해 SHIFT의 QR을 휴대폰으로 스캔한다. 차량 화면의 간단한 확인 코드(PIN)를 휴대폰에서 입력하고 승인하면 차량 앱에 자동 로그인한다. 탑승자가 차량에서 직접 요청을 확인해 인증하는 방식이다.

### 내 방문 업무에서 차량 내비로 목적지 전달

차량 화면에 오늘 방문 일정과 관련 메일을 보여준다. 변경된 방문 장소가 있으면 장소 후보와 일정 또는 메일의 근거를 표시한다. 직원이 확인한 목적지를 NaviHelper SDK로 Pleos 기본 내비에 전달해 주소 재입력을 줄인다.

### 방문 후 메모와 개인 세션 종료

방문을 마친 직원은 주차 상태에서 음성으로 메모를 작성하고 인식 결과를 확인한 뒤 저장한다. 음성 인식에는 Pleos SpeechToText SDK를 쓰고, 메모를 OneNote로 연결하는 방식을 검증한다.

차량 화면에서 로그아웃 QR을 열어 휴대폰으로 승인하면 SHIFT의 개인 세션과 앱 내 개인 화면·캐시를 정리한다. 앞선 직원이 종료하지 않았더라도 새 탑승자가 인증에 성공하면 이전 차량 세션을 만료시키고 새 직원의 업무를 불러온다.

## 4 대표 이용 장면

배정받은 차량 탑승 → SHIFT 인증 → 내 방문 업무 확인 → 목적지 전달 → 방문 후 메모 → 개인 세션 종료

1. 외근 직원 A가 회사에서 배정받은 공용차에 탄다.
2. 차량 화면에서 QR을 열고 휴대폰으로 스캔한다. 간단한 PIN을 입력해 승인하면 차량에 A의 업무 화면이 열린다.
3. A는 오늘 방문 일정과 미팅 장소가 바뀌었다는 메일을 확인한다.
4. 변경 주소와 근거를 확인하고 Pleos 차량 내비로 목적지를 전달한다.
5. 방문을 마친 뒤 주차 상태에서 상담 메모를 음성으로 입력한다. 변환된 내용을 확인하고 저장한다.
6. A가 차량의 로그아웃 QR을 휴대폰으로 승인하면 개인 세션이 끝난다. 같은 차량에 탑승한 직원 B는 자신의 계정으로 인증해 B의 업무를 본다.

시제품에서는 가상의 직원 A와 B, 시험 차량과 합성 업무 데이터를 사용한다. A가 로그아웃을 잊고 B가 같은 차량에서 새로 인증하는 경우도 확인한다.

## 5 구현과 검증 계획

차량 화면은 Kotlin 기반 Pleos Connect Android 앱으로 개발한다. 휴대폰 브라우저는 QR 승인에 사용한다. Node.js·TypeScript HTTPS 서버가 QR 요청과 차량 세션을 관리하고, PostgreSQL에 시연용 조직·차량과 세션 정보를 저장한다. 시연 서버는 AWS 서울 리전 Lightsail을 기본안으로 검토한다.

| 연결 대상 | 구현·검증 항목 |
| --- | --- |
| Microsoft Graph | Outlook 일정·메일과 OneNote를 연동할 수 있는지 시험 계정과 사용자 위임 권한으로 검증한다. |
| NaviHelper SDK | 사용자가 확인한 목적지를 Pleos 내비에 전달하고 요청 완료·실패를 확인한다. |
| SpeechToText SDK | 주차 상태에서 입력한 한국어 음성을 변환하고 사용자가 확인한 메모를 저장한다. |
| 차량 세션 | QR 로그인·로그아웃, 같은 차량의 A→B 교대와 이전 세션 접근 차단을 확인한다. |
| 주행 규제 | CarUxRestrictions로 주차·주행 전환 시 차량 화면과 입력이 어떻게 제한되는지 검증한다. |

Pleos Connect Emulator 2.1.0의 공식 기본 화면인 2560 × 1440 px와 공식 윈도우 정책을 참고해 시안을 설계한다. SHIFT는 앱 윈도우 안에서 실행하며, 에뮬레이터에서 창 크기에 따른 배치와 주행 규제를 확인한다. [Pleos 디자인 가이드](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro) · [공모전 개발 범위](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)

1차에는 화면 시안과 클릭형 프로토타입 영상으로 핵심 흐름을 보여준다. 2차 PT는 Pleos 에뮬레이터에서 실제 인증, 목적지 전달, 메모와 세션 교대를 시연하는 것을 목표로 한다. 시험 데이터와 실제 동작을 자료에 표시한다.

## 6 제공 가치와 확장

직원은 일정과 메일에서 찾은 주소를 차량 내비에 다시 입력하는 단계를 줄이고, 방문 직후 상담 메모를 남길 수 있다. 공용차가 교대될 때 이전 직원의 SHIFT 업무 접근을 끊는 동작을 두 직원의 연속 탑승으로 검증한다. 방문 준비에 걸린 시간, 메모 저장 성공 여부, 교대 후 정보 분리를 측정한다.

우선 현대자동차의 사내 공용차 이용 상황을 시제품으로 구현한다. 여러 회사가 등록되는 구조는 A회사, B회사, 현대로 예시를 들고, 실제 동작 범위는 현대 시나리오에 둔다. 향후 팀이 회사 관리자를 지정하면 관리자는 차량 이용 권한을 부여하고 직원은 권한을 요청할 수 있다. 등록 코드 또는 QR을 통한 차량 등록과 SHIFT 내 예약도 후속 개발 방향으로 제안한다.

실제 사내 실증을 통해 운영 적합성과 반복 이용 가능성을 확인한 뒤 외부 기업의 공용차로 확대할 수 있다. 실증 규모, 예상 활성 이용자와 재이용 목표는 시제품 시험과 운영 부서 협의 후 정한다.
