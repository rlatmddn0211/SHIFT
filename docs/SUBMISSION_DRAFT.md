# SHIFT 공모전 작품 소개 초안

2026년 11월 14일 확정 기획을 반영한 공식 접수양식용 본문이다. [저장소 README](../README.md)와 같은 기능 범위를 사용하며 [기획안](PLAN.md)과 [결정 기록](DECISIONS.md)을 함께 갱신한다.

## 1 앱 한 줄 소개

SHIFT는 공용차의 Pleos Connect에서 개인별 좌석 설정을 적용하고 방문 업무·내비게이션·음성 메모를 이어 쓰며, 교대 시 개인 세션을 정리하는 앱입니다.

## 2 기획 배경

회사 공용차는 여러 직원이 번갈아 사용합니다. 같은 직원도 방문 일정에 따라 다른 차량을 배정받아 좌석의 높이와 앞뒤 위치를 다시 맞춰야 합니다. 방문 장소가 바뀌면 휴대폰에서 일정과 메일을 확인한 뒤 차량 내비게이션에 주소를 다시 입력하고, 방문 후 남긴 메모도 업무 도구로 옮겨야 합니다.

SHIFT는 휴대폰 모바일 웹에서 연결한 업무 계정과 개인 프로필을 현재 탑승한 차량에 불러옵니다. 직원은 출발 전에 방문 업무를 확인하고, 저장한 좌석 설정을 지원 범위 안에서 적용하며, 확인한 방문지를 차량 내비게이션에 전달합니다. 방문 후에는 음성으로 작성한 메모를 확인해 저장하고 휴대폰에서도 이어서 봅니다.

이용이 끝나면 해당 차량의 개인 세션을 정리하고 다음 직원은 자신의 환경으로 업무를 시작합니다. 차가 바뀌어도 업무와 선호하는 착석 환경을 이어 쓰도록 돕는 것이 SHIFT의 목표입니다.

## 3 앱 주요 기능 및 차량 특화 요소

### 휴대폰 모바일 웹에서 업무·개인 프로필 준비

별도 SHIFT 휴대폰 앱 설치 없이 모바일 웹에서 Microsoft 365 업무 계정을 연결합니다. 차량에 가져올 일정·메일·OneNote 노트와 음성으로 알릴 업무 업데이트를 선택하고, 개인별 좌석 설정 프로필을 준비합니다. 업무 서비스 접근은 사용자가 동의한 기능에서만 수행합니다.

### Pleos에서 QR·PIN으로 로그인하고 교대

차량 화면의 QR을 휴대폰으로 스캔한 뒤, 회사 계정으로 로그인된 모바일 웹에서 차량과 일회용 PIN을 확인해 승인합니다. 승인이 끝나면 차량에 해당 직원의 업무 환경을 불러옵니다. 이용 종료는 차량의 로그아웃 QR을 휴대폰으로 승인하는 방식으로 처리합니다.

이전 직원이 로그아웃을 놓쳤더라도 새 탑승자의 인증이 완료되면 기존 SHIFT 차량 세션을 만료시키고 새 직원의 업무 화면을 엽니다. 차량마다 활성 개인 세션은 하나만 유지합니다.

### 개인별 좌석 높이·위치 적용

운전석의 높이와 앞뒤 위치를 개인 프로필로 저장하고 다음 탑승 때 불러오는 기능을 구현·검증합니다. 정차 상태에서 사용자가 적용할 설정을 확인한 뒤, 해당 차량이 지원하는 항목과 허용 범위 안에서 적용합니다. 차종별 지원 여부와 값의 범위는 실제 SDK·에뮬레이터에서 확인합니다. 공조와 조명 설정은 이번 출품 범위에 포함하지 않습니다.

### AI 음성 브리핑과 방문지 안내

사용자가 선택한 새 업무 메일의 핵심과 방문 일정의 시간·장소 변경을 AI로 짧게 요약해 출발 전에 음성으로 안내합니다. 원본 일정·메일과 장소 후보를 함께 보여주고, 직원이 확인한 목적지만 Pleos 내비게이션으로 전달합니다. 방문 후 주차 상태에서는 상담 내용을 말하고 변환된 메모를 확인해 OneNote에 저장합니다.

### 휴대폰 음악을 차량 오디오로 이어 듣기

휴대폰에서 이용하던 음악을 공식 음악 앱과 차량 오디오 연결을 통해 이어 듣는 경로로 검증합니다. 기존 후보인 YouTube Music도 이 경로에서 확인합니다. 실제 계정의 재생, 차량 오디오 출력과 지원되는 조작 범위를 시험하며, SHIFT가 음악 서비스의 재생목록을 직접 불러오거나 제어하는 기능으로 표현하지 않습니다.

### 향후 확장: 회사별 공용차 예약과 관리

회사·차량 등록, 직원 이용 권한 요청·승인, 차량 목록과 예약·취소·연장, 관리자 운영 화면은 후속 확장입니다. 이번 시제품은 회사의 기존 절차로 차량을 배정받은 상태에서 시작합니다. 예약 기능의 효과와 예약 중복 방지는 해당 기능을 구현한 뒤 별도로 검증합니다.

## 4 주요 사용 시나리오

최초 준비로 직원 A는 휴대폰 모바일 웹에서 업무 계정을 연결하고 차량에 표시할 노트와 업무 업데이트, 좌석 프로필을 준비합니다.

1. **배정받은 차량 탑승.** A는 회사의 기존 절차로 배정받은 공용차에 탑승합니다.
2. **SHIFT 인증.** 차량 QR을 스캔하고 모바일 웹에서 PIN으로 승인합니다. A의 방문 업무와 개인 메모를 불러오고, 정차 상태에서 확인한 좌석 설정을 지원 범위 안에서 적용합니다. 음악은 휴대폰의 공식 앱과 차량 오디오 연결 경로로 이용합니다.
3. **내 방문 업무 확인.** 출발 전 SHIFT가 “오후 두 시 미팅 장소가 변경됐습니다”라고 요약해 안내합니다. A는 관련 메일의 원문과 변경 주소를 확인합니다.
4. **목적지 전달.** A가 확인한 주소를 선택하면 Pleos 내비게이션에 목적지를 전달하고 경로 요청의 완료·실패 결과를 표시합니다.
5. **방문 후 메모.** 방문을 마친 A는 주차 상태에서 “금요일까지 수정 견적을 보내기로 함”이라고 말합니다. 변환된 내용을 확인해 OneNote에 저장하고 이후 휴대폰에서도 확인합니다.
6. **개인 세션 종료.** A가 로그아웃 QR을 휴대폰으로 승인하면 해당 차량의 SHIFT 세션과 개인 화면·캐시를 정리합니다. 다음 직원 B가 인증하면 B의 업무와 좌석 프로필을 불러옵니다. A가 종료를 놓쳤더라도 B의 인증 완료 시 A의 차량 세션은 만료됩니다.

시제품은 현대자동차 사내 공용차 이용 상황을 가정한 시험 차량과 가상의 직원 A·B, 실제 고객 정보와 구분된 시험 데이터를 사용합니다.

## 5 개발 계획

차량 화면은 Kotlin 기반 Pleos Connect Android 앱으로 개발합니다. 휴대폰 모바일 웹은 업무 계정 연결, 개인 프로필 준비와 QR·PIN 승인에 사용합니다. Node.js·TypeScript 서버와 PostgreSQL로 사용자 프로필과 차량별 세션을 관리합니다.

- **업무와 메모:** Microsoft Graph의 사용자 위임 권한으로 Outlook 일정·메일 조회와 OneNote 노트 조회·새 메모 저장을 검증합니다. 회사·학교 Microsoft 365 시험 계정의 서비스 이용 가능 여부와 조직 동의도 확인합니다.
- **내비게이션과 음성:** NaviHelper SDK로 사용자가 확인한 목적지를 전달하고 결과 이벤트를 확인합니다. AI 요약문은 Pleos TextToSpeech SDK로 안내하고, 방문 후 음성은 SpeechToText SDK로 텍스트로 변환합니다. 화면·입력·음성 기능은 주행 상태와 앱 카테고리의 제한에 맞춰 시험합니다.
- **좌석 개인화:** 공개 Vehicle SDK의 좌석 높이·앞뒤 위치 조회, 이동 및 capability·권한을 확인해 적용합니다. 저장값은 차량별 지원 범위 안에서 처리하고 적용 결과를 표시합니다. 공조·조명은 제외합니다. [공식 Seat API](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/seat/entry)
- **음악:** 휴대폰의 공식 음악 앱에서 재생한 소리를 차량 오디오로 이어 듣는 경로와 지원되는 조작을 검증합니다. SHIFT 인증과 휴대폰 오디오 연결은 역할을 구분합니다.
- **세션과 교대:** 차량마다 활성 세션 하나를 유지하고 새 인증 완료 시 이전 세션의 접근을 끊습니다. 종료 후 SHIFT가 관리하는 개인 화면·캐시를 정리하며, 원본 메일·일정과 OneNote에 저장한 메모는 각 서비스에 남깁니다.
- **시제품 검증:** Pleos Connect 에뮬레이터에서 A·B 연속 이용으로 인증, 좌석 적용, 업무 확인, 목적지 전달, 실제 메모 저장과 개인 정보 분리를 확인합니다. 1차 클릭형 시안과 실제 SDK·서비스 연동 결과는 구분해 제시합니다.

라이브러리 호환 버전, AI 요약·주소 검색 수단, 배포와 데이터 보관 정책 등은 구현·시험 과정에서 확정합니다.

## 6 기대효과 및 발전 가능성

SHIFT를 **현대자동차가 기업 공용차에 적용할 수 있는 서비스**로 제안합니다. 직원이 차량을 바꿔 타더라도 자신의 좌석 설정과 업무 환경을 이어 쓰고, 방문지 재입력과 상담 메모 정리 부담을 줄이며, 교대 시 차량의 개인 업무 접근을 끝내도록 돕습니다.

첫 시제품은 현대자동차 사내 공용차 이용 상황을 가정해 개발합니다. 기존 방식과 비교해 탑승 후 올바른 목적지 전달까지 걸리는 시간, OneNote 메모의 실제 저장 성공률, A/B 전환 후 이전 직원 정보의 접근 차단 여부를 측정합니다. 좌석 설정 적용 결과와 음악의 차량 오디오 연결도 별도로 확인합니다. 아직 측정하지 않은 개선율이나 도입 실적은 제시하지 않습니다.

핵심 경험을 검증한 뒤 다른 기업의 공용차로 적용 범위를 넓히고 회사별 차량 등록·이용 권한·예약·관리 기능을 확장할 수 있습니다. 예약·배정 시간의 개선은 확장 기능을 구현한 뒤 측정합니다. MAU와 4주 재이용률은 실제 도입 후 지속 이용을 확인하는 운영 지표로 구분합니다.
