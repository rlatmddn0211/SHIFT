# SHIFT 결정 기록

이 문서는 2026년 11월 14일 기준의 합의를 반영한다. 이전 결정 기록은 Git 이력에서 확인할 수 있다. 루트 README의 최종 앱 설명과 같은 범위를 사용한다.

## 확정 사항

| 항목 | 결정 |
| --- | --- |
| 대표 흐름 | 배정받은 차량 탑승 → SHIFT 인증 → 내 방문 업무 확인 → 목적지 전달 → 방문 후 메모 → 개인 세션 종료 |
| 개발 우선순위 | Pleos Connect 차량용 Android 화면부터 구현한다. 휴대폰은 별도 SHIFT 앱 없이 모바일 웹으로 업무 계정·프로필을 준비하고 QR 인증·종료를 승인한다. |
| 회사 범위 | A회사, B회사, 현대를 여러 회사 등록 구조의 예로 제시한다. 동작하는 시제품은 현대 시나리오만 구성한다. |
| 차량 배정 | 직원이 회사에서 이미 배정받은 차량에 탑승하는 상황을 전제로 한다. SHIFT의 예약 기능은 향후 개발 방향이다. |
| 차량 로그인 | 탑승자가 차량 화면의 QR을 휴대폰으로 스캔하고 간단한 PIN으로 승인하면 차량 앱에 자동 로그인한다. |
| 탑승자 우선 | 예약 시각 대신 차량에서 요청을 승인한 탑승자가 우선한다. 새 인증이 완료되면 기존 차량 세션은 만료된다. |
| 차량 로그아웃 | QR은 로그인과 로그아웃에 사용한다. 로그아웃을 승인하면 해당 SHIFT 차량 세션을 정리한다. |
| 방문 업무 | Microsoft 365 Outlook 메일·일정을 연동 대상으로 유지한다. 오늘 일정과 관련 메일의 근거를 제시하고, 사용자 확인 후 Pleos 내비에 목적지를 전달한다. 업무 연동은 사용자가 선택한다. |
| 방문 후 메모 | 음성 입력 내용을 확인한 뒤 새 메모를 저장한다. 기존 연동 대상은 OneNote이며 기존 노트 편집은 범위에서 제외한다. |
| 차량 물리 제어 | 좌석 높이·앞뒤 위치 개인화를 출품 범위에 다시 포함한다. 정차 상태에서 사용자 확인 후 지원 항목·범위 안에서 적용한다. 공조·조명은 제외한다. |
| 음악 | 휴대폰에서 이용하던 음악을 공식 음악 앱과 차량 오디오로 이어 듣는 경로로 검증한다. SHIFT 자체 재생목록 조회·플레이어 제어는 확정 기능으로 쓰지 않는다. |
| 음성 브리핑 | 사용자가 선택한 업무 메일과 일정의 시간·장소 변경을 AI로 요약해 출발 전에 TextToSpeech로 안내한다. |
| 장기 제안 | 현대자동차가 기업 공용차에 적용할 수 있는 서비스로 제안한다. 공식 도입·제휴 확정으로 표현하지 않는다. |
| 검증 | 목적지 전달까지의 시간, 실제 메모 저장 성공률, A/B 이전 정보 접근 차단을 우선 측정한다. 예약 효율은 확장 구현 후, MAU·4주 재이용률은 실제 운영 단계에서 확인한다. |
| 참가와 제출 | 대학생 부문 2명, 앱 이름 SHIFT. 1차는 기획서·화면 시안·클릭형 시연 영상으로 준비한다. |
| 화면 시안 | 필요 시 공식 Pleos Figma 자료를 활용한다. 에뮬레이터의 전체 화면과 SHIFT 앱 윈도우를 구분한다. |

## 향후 확장

| 항목 | 결정 또는 방향 |
| --- | --- |
| 회사와 관리자 | 여러 회사가 등록 가능한 구조를 제안한다. 회사 관리자는 팀에서 직접 지정한다. |
| 차량 권한과 등록 | 관리자가 이용 권한을 부여하고 직원은 권한을 요청한다. 차량 등록은 등록 코드나 QR을 사용한다. |
| 예약 | SHIFT의 예약, 즉시 이용, 취소·연장과 중복 확인은 향후 확장으로 제시한다. 예약 종료 알림과 유예·보유 정책은 미정이다. |
| 운영 기록 | 회사 공개 기록은 예약·이용 시간과 수동 인계 메모를 기준으로 한다. 기록의 세부 범위·실증 규모·목표 수치는 후속 설계와 협의 때 정한다. |

## 기술 기본안

널리 쓰이는 기술을 기준으로 차량은 Kotlin, 모바일 승인과 API는 Node.js LTS·TypeScript 단일 HTTPS 서비스, 데이터 저장은 PostgreSQL, 시연 배포는 AWS 서울 리전 Lightsail을 기본안으로 기록한다. Lightsail 인스턴스와 비공개 관리형 PostgreSQL을 검토하며, 비용·계정·도메인 등 운영 설정은 추후 확정한다. [개발 구성과 근거](PLAN.md#6-개발-구성)

## 이후에 정할 항목

- 팀명, 팀원별 역할·투입 시간, 시안과 영상의 제작 도구 및 담당
- PIN 길이·만료 시간, 인증 실패·동시 승인·오프라인 처리, 원격 종료 정책
- Microsoft 365 시험 계정과 조직 동의, 연동 해제 처리, 요약 및 주소 검색 방식과 외부 서비스 데이터 처리
- OneNote 조회 범위, 섹션 선택·생성, 저장 오류 및 재시도 동작
- 주행 상태에서 제공할 상세 기능, 시연 대상 창 규격과 검증 장비
- 좌석 지원·허용 범위와 차량별 선호값 적용, 음악의 휴대폰·차량 오디오 연결 및 조작 지원, 인계 메모·차량 상태 범위
- 향후 예약 종료 알림, 유예 시간, 기록 보유 기간 및 실제 사내 실증의 규모와 수치 목표
