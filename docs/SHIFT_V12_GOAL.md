# SHIFT v1.2 구현 목표 프롬프트

[최종 기획안 v1.2](https://github.com/rlatmddn0211/SHIFT/blob/aeda8d4c3b82be50da4d7a23d391b591580507f5/docs/PLAN.md)를 기준으로 기존 `codex/pleos-screen-dev`의 남색 Android 화면과 QR·PIN 로그인을 이어서 구현한다. 공용차에 직원 A와 B가 교대로 탑승하는 시제품을 Pleos Connect Emulator 2.1.0에서 검증한다.

먼저 기존 Figma 작업 파일에 편집 가능한 화면과 클릭형 시연 흐름을 만든다. Figma에서 시연한 화면과 동작을 차량 앱 및 모바일 웹에 적용한다.

1. 휴대폰 웹에서 업무 계정 동의와 브리핑·노트 선택, 운전석 높이와 앞뒤 위치 프로필 설정을 제공한다. Microsoft Graph에 사용자 위임 권한으로 연결하고 시연 계정별 시험 데이터를 제공한다.
2. 정차 상태에서 운전석 프로필을 확인한 후 Seat SDK가 지원하는 항목과 범위 안에서 적용한다. 적용 결과와 지원 여부를 표시한다.
3. 개인별 방문 일정, 관련 메일, 장소 변경의 근거와 후보를 보여준다. 선택한 메일과 일정 변경을 짧게 요약하고 Pleos 음성 합성으로 브리핑한다.
4. 확정한 위치를 Pleos 기본 내비에 전달한다. NaviHelper의 응답을 근거로 결과를 알린다.
5. 주차 상태에서 음성을 인식하고 직원이 확인·수정한 내용을 새 방문 메모로 저장한다. OneNote 연동에서는 새 페이지로 저장한다.
6. 차량에 묶인 종료 QR을 휴대폰에서 승인하면 해당 세션을 종료하고 공용 대기로 돌아간다. 직원 B가 교대 인증하면 A의 세션, 화면 및 진행 중 응답을 정리한다. QR 만료, 재사용, 동시 요청과 교대 중 이전 응답을 확인한다.
7. 휴대폰 공식 음악 앱과 차량 오디오 연결 경로를 안내하고 가능한 환경에서 재생을 검증한다. 주행 중 사용할 수 있는 화면은 Pleos 주행 규제를 따르게 한다.

각 기능은 차량 앱과 서버의 실제 진입점에서 실행할 수 있어야 한다. 시험 계정, 기기 또는 SDK가 필요한 검증은 필요한 조건과 확인 결과를 기록한다. 시연 결과와 실제 서비스의 결과는 UI에서도 구분한다. API 키, 계정 비밀과 개인 데이터는 저장소에 포함하지 않는다. 회사·차량 등록, 권한 관리, 예약은 v1.2 §7의 후속 범위로 유지한다.

기능별로 관련 변경을 커밋하고 기존 브랜치에 푸시한다. 서버 테스트, Android 빌드와 lint, Pleos 화면과 대표 사용자 흐름을 검증한다. 기능별 실행 방법, 검증 범위와 대표 실행 캡처를 브랜치에 함께 남긴다.
