# SHIFT 전체 기획안 v1.1

작성 기준일: 2026년 11월 13일

SHIFT는 이미 배정받은 공용차에서 직원의 방문 업무 환경을 이어 쓰고, 이용을 마칠 때 개인 세션을 정리하는 차량용 서비스다. 휴대폰에서는 계정과 개인 환경을 준비하고, 차량에서는 방문 준비와 기록을 수행한다. 사용자와 확정한 범위는 [결정 기록](DECISIONS.md), 디자인·협업·시연·검증 방식은 [제작 계획](DELIVERY_PLAN.md)에서 관리한다.

**확정한 핵심 흐름: 배정받은 차량 탑승 → SHIFT 인증 → 내 방문 업무 확인 → 목적지 전달 → 방문 후 메모 → 개인 세션 종료.**

사내 차량 관리 앱은 확장으로 넘긴다. 차량 배정·예약·대여 승인·차량 반납 처리와 이를 위한 관리자 화면은 이번 출품의 필수 구현과 시연에 포함하지 않는다. 기존 회사 절차로 차량을 배정받았다는 상태에서 SHIFT 이용을 시작한다.

## 1 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | SHIFT, 시프트 |
| 소개 문구 | 공유차량을 나의 업무 공간으로 |
| 주요 사용자 | 우선 현대자동차 사내 공용차로 고객사를 방문하는 영업·외근 직원 |
| 기본 이용 환경 | Pleos Connect 차량용 Android 앱과 휴대폰 모바일 웹 |
| 업무 계정 | Microsoft 계정, Outlook 또는 Microsoft 365 |
| 노트 연동 대상 | Microsoft OneNote |
| 음악 연동 목표 | YouTube Music 실제 이용. 공식 직접 연동을 검증하고 휴대폰 공식 앱·차량 오디오 경로도 허용 |
| 관리 위치 | GitHub SHIFT 저장소 |

참가 구성은 대학생 부문 2명이며 팀명은 미정이다. SHIFT는 앱 이름으로 유지한다. 팀원별 담당과 개발 투입 가능 시간은 사용자가 미정으로 남기기로 했다.

직원이 이용할 차량을 바꾸더라도 자신의 계정과 업무·노트·음악 환경을 이어갈 수 있도록 한다. 개인 환경은 사용자에게 연결하고, 차량에 부여하는 접근은 이용 세션에 연결한다.

제품을 설명할 때는 “배정받은 공용차에서 내 방문 업무를 이어 쓰고, 이용이 끝나면 내 업무 연결을 정리하는 서비스”를 중심으로 소개한다. 개인 세션 종료는 해당 차량에서 SHIFT의 개인 접근을 끝내는 동작이다.

메일과 일정뿐 아니라 노트와 음악 서비스의 실제 연동도 구현 목표에 포함한다. YouTube Music의 차량 재생 방식은 지원 검증이 필요한 요구사항이며, 구현이 확인된 기능과 동일하게 표현하지 않는다.

공조·풍량·조명 등 물리적 차량 설정은 이번 출품 범위에서 제외한다. 개인화의 중심은 업무 계정, 선택한 노트, 음악과 현재 이용자의 세션을 전환하는 경험이다.

## 2 해결할 문제

다음 문제를 사용자 인터뷰와 시제품 시험으로 검증한다.

- 공용차를 바꿀 때마다 업무 계정과 개인 서비스를 연결하고 사용할 정보를 다시 찾아야 한다.
- 휴대폰의 일정이나 메일에서 방문 장소를 확인한 뒤 차량 내비게이션에 다시 입력해야 한다.
- 개인 노트와 업무 정보를 차량에서 활용하려면 여러 기기와 앱을 오가야 한다.
- 이용 종료 후 개인 계정이나 업무 정보가 차량에 남을 수 있어 정리 부담이 생긴다.
- 직원이 교대할 때 이전 직원의 개인 업무 정보가 다음 직원에게 노출될 수 있다.

반복 설정에 걸리는 시간이나 정보 노출 빈도는 아직 실측하지 않았다. 실제 측정 전에는 개선율이나 이용률을 성과로 제시하지 않는다.

공조 온도와 풍량은 날씨와 탑승 상황에 따라 달라진다는 사용자 의견을 반영한다. 이런 항목의 고정값 복원을 핵심 문제로 내세우지 않는다.

## 3 사용자와 역할

| 역할 | 수행할 일 | 정할 정책 |
| --- | --- | --- |
| 직원 | 회사 인증, 서비스 연동, 방문 준비·기록, 개인 세션 종료 | 서비스 동의, 세션 잠금과 연결 해제 |
| 시험 환경 설정 담당 | 시험용 회사·차량 식별정보와 허용 조직을 사전 설정 | 등록된 회사·차량과 인증 세션의 연결 |
| 차량의 SHIFT 앱 | 이용자 인증, 업무 환경 표시, 노트와 음악 연결, 세션 정리 | 주행 중 기능 제한, 종료 처리 |

첫 적용 대상은 현대자동차 사내 공용차를 이용하는 영업·외근 직원이다. 사내 운영·IT 부서를 도입 협의 대상으로 제안하며, 내부 활용 검증 후 외부 기업의 공용차로 확대하는 방향이다. 현대자동차의 도입이나 협력이 확정된 것은 아니고, 실제 사내 인증·업무 도구와의 연동은 실증 전에 확인한다.

문제 확인을 위한 인터뷰는 다른 회사의 공용차 이용 외근 직원과 차량 운영자에게도 진행할 수 있다. 사용자에게 인터뷰 가능성이 있으나 실제 참여자는 아직 확정되지 않았다. 타사 인터뷰 결과와 현대자동차 사내 실증을 구분해 기록한다.

## 4 전체 사용자 흐름

### 최초 준비

1. 시험용 회사·차량 식별정보와 회사의 허용 Microsoft 조직을 사전 설정한다. 관리 화면을 만들지 않아도 핵심 흐름을 시연할 수 있도록 한다.
2. 직원이 회사 초대 링크를 열고 Microsoft 계정으로 인증한다.
3. 초대 링크의 회사에 등록된 Microsoft 조직 계정이면 즉시 가입한다.
4. 직원이 메일, 일정과 OneNote의 연동을 준비하고 음악 이용 경로를 확인한다.
5. 휴대폰에서 차량에 가져올 OneNote 노트를 선택한다. 음성 메모는 개인 OneNote의 전용 섹션에 저장하도록 준비한다.

회사 허용 여부는 등록된 Microsoft 조직 계정을 기준으로 확인한다. 초대 링크의 회사와 인증된 조직이 일치하는지 확인하며, 링크를 가졌다는 이유만으로 다른 조직 계정의 가입을 허용하지 않는다. 개인 서비스의 동의를 회사 가입 동의와 동일한 것으로 취급하지 않는다. 최초 연동에서 각 서비스에 동의한 뒤 반복 탑승에서는 차량 이용 승인으로 이어가는 경험을 목표로 한다.

업무 서비스 연동은 선택이다. 회사 계정으로 가입한 직원은 메일·일정·OneNote 접근 권한을 주지 않아도 인증과 세션 관리를 이용할 수 있다. 연동하지 않은 업무 기능은 연결이 필요한 상태로 표시하고, 동의를 받기 전에 내용을 조회하지 않는다.

### 차량 이용

1. **배정받은 차량 탑승:** 기존 회사 절차로 배정받은 차량에 탑승한다.
2. **SHIFT 인증:** 차량 앱의 QR을 휴대폰에서 확인하고 현재 차량에 업무 환경을 연결할 것을 승인한다.
3. **내 방문 업무 확인:** 오늘 일정, 최근 7일의 관련·중요 메일과 선택한 OneNote 노트로 방문을 준비한다.
4. **목적지 전달:** 원본 근거와 장소 후보를 확인한 뒤 차량 내비게이션에 목적지를 전달한다.
5. **방문 후 메모:** 방문을 마친 뒤 주차 상태에서 음성으로 메모를 작성하고 내용을 확인해 개인 OneNote 전용 섹션에 저장한다.
6. **개인 세션 종료:** 차량에서 개인 업무 연결을 끝내고 앱 내 개인 데이터 정리 결과를 확인한다.

같은 세션이 유효하면 앱을 다시 열었을 때 이어간다. 다음 직원의 연결은 새로운 승인으로 구분한다. 수동 종료와 휴대폰 원격 종료를 제공하고, 일정 시간 비활동 후 개인 세션을 잠근다. 비활동 기준과 시간은 시험 후 확정하며 예약 시간에 의존하지 않는다.

QR 승인은 SHIFT의 이용자와 차량 세션을 연결하는 절차다. 휴대폰 오디오를 차량으로 전달하는 Bluetooth 등과는 역할이 다르며, QR 승인만으로 음악의 오디오 연결이 완료된다고 가정하지 않는다.

### 이용 상태의 구분

| 상태 | 직원이 볼 내용 | 확인할 조건 |
| --- | --- | --- |
| 인증 대기 | 현재 차량의 QR과 연결 상태 | 휴대폰에서 해당 차량 이용을 승인했는지 |
| 개인 업무 이용 | 현재 직원의 업무 환경과 연결 결과 | 인증과 서비스 동의가 유효하고 해당 직원의 정보만 조회되는지 |
| 세션 잠금 | 개인 정보가 가려진 잠금 상태 | 만료 또는 원격 종료 후 기존 접근이 차단되는지 |
| 개인 세션 종료 처리 | 개인 연결과 데이터의 정리 결과 | 앱 데이터 정리와 해당 세션의 서버 접근 종료 여부 |
| 공용 대기 | 다음 직원이 시작할 수 있는 화면 | 이전 직원의 정보가 보이거나 다시 조회되지 않는지 |

서비스별 연결 실패는 해당 서비스의 상태로 표시한다. 음악 연결 실패가 다른 업무 기능을 막지 않도록 하고, OneNote 저장 실패를 완료로 표시하지 않는다. 재시도와 잠금 해제의 상세 동작은 구현 설계에서 검토한다.

## 5 기능 요구사항

| 기능 | 요구 내용 | 구체화할 부분 |
| --- | --- | --- |
| 회사 가입 | 초대 링크로 접속하고 등록된 회사의 Microsoft 조직 계정이면 즉시 가입한다 | 초대 링크 관리와 조직 확인 구현 |
| 서비스 연동 | 메일, 일정, OneNote와 음악을 연결한다 | 계정 종류, 동의 범위, 연결 해제 |
| 개인 프로필 | 연결 상태와 선택한 노트 등 최소 설정을 계정에 보관하고 사용자가 연결 해제할 수 있게 한다 | 연결 해제 시 영향, 계정 삭제 절차 |
| 탑승 인증 | 현재 차량과 현재 사용자를 QR 승인으로 연결한다 | 인증 유효시간, 차량 식별정보의 사전 설정 |
| 업무 목적지 | 오늘 일정과 관련 메일에서 방문 장소를 제안하고 사용자 확인 후 내비게이션에 전달한다 | 주소의 불확실성 처리, 변경된 일정 반영 |
| 중요 메일 | 오늘 일정·관련 메일·중요 메일을 요약한다 | 중요도 기준, 음성 안내, 원문 표시 범위 |
| OneNote | 휴대폰에서 선택한 노트를 조회하고 음성 메모를 개인 전용 섹션에 저장한다 | 저장 전 확인, 저장 실패와 재시도 |
| 음악 | YouTube Music의 실제 이용을 연결한다 | 차량 직접 연동 검증, 휴대폰 공식 앱 및 차량 오디오 경로 |
| 개인 세션 종료 | 차량 앱의 개인 접근과 데이터를 정리한다 | 종료 조건, 정리 대상, 재시도 |
| 종료 누락 대응 | 수동·휴대폰 원격 종료와 비활동 후 자동 잠금을 제공한다 | 비활동 판정, 잠금 시간과 재인증 |

1차 클릭형 프로토타입과 PT의 실제 앱 개발 목표를 구분한다. 실제 구현하기로 한 목표를 목업으로 대체하려면 범위를 다시 협의한다. 기획서와 시연 영상에는 실제 연동, 시연 데이터, 미구현 기능을 구분한다.

## 6 화면 구성안

화면 구조는 아래 흐름을 설명하기 위한 초안이다. 화면별 버튼, 정보량과 주행 상태에 따른 동작은 세부 정책을 확정한 뒤 검토한다.

| 구분 | 화면 | 주요 내용 |
| --- | --- | --- |
| 휴대폰 | 회사 가입 | 초대 정보, 회사 인증, 가입 상태 |
| 휴대폰 | 현재 연결 | 현재 차량의 개인 세션과 원격 종료 |
| 휴대폰 | 연동 서비스 | Outlook, 일정, OneNote, 음악의 연결 상태 |
| 휴대폰 | 내 업무 환경 | 사용할 노트와 개인 서비스의 준비 상태 |
| 휴대폰 | 차량 연결 승인 | 연결할 차량과 사용자 확인 |
| 차량 | 시작 및 인증 | QR, 인증 대기, 연결 결과 |
| 차량 | 내 환경 연결 | 현재 이용자, 서비스별 연결 결과 |
| 차량 | 내 업무 | 방문 일정, 메일, 노트의 진입점 |
| 차량 | 목적지 확인 | 장소 후보, 근거, 내비게이션 연결 |
| 차량 | 음악 | 개인 재생목록과 재생 상태 및 조작 |
| 차량 | 방문 후 메모 | 음성 입력, 인식 내용 확인, OneNote 저장 결과 |
| 차량 | 개인 세션 종료 | 종료 확인, 개인 데이터 정리 결과, 공용 대기 |

기존 디자인 자료는 없다. 차량 화면은 짙은 배경의 차분한 업무 도구로, 휴대폰은 밝고 간결한 화면으로 만든다. 관리자 등록과 예약 취소 화면은 1차 시안·영상에 포함하지 않는다.

## 7 업무 정보와 노트

Microsoft Graph를 이용하는 연동을 검토한다. 회사 계정 인증, 메일과 일정 접근, OneNote 접근은 각각 필요한 권한을 확인한다. 사용자는 시험에 사용할 회사·학교 Microsoft 365 계정을 보유하고 있다. 해당 계정의 메일함과 OneNote 이용 가능 여부, 앱 등록 환경과 조직 동의 정책은 실제 연결 과정에서 확인한다.

목적지는 원본 일정이나 메일의 근거를 함께 보여준다. 주소나 시간이 불분명한 경우에는 사용자가 후보를 확인하도록 한다. 목적지 변경과 기타 업무 작업의 실행 범위는 별도로 정한다.

메일·일정의 출품 범위는 오늘 일정, 관련 메일과 중요 메일의 요약 및 목적지 제안이다. 답장 초안과 메일 발송은 포함하지 않는다. 목적지를 변경하기 전에는 원본 근거와 후보를 보여주고 사용자 확인을 받는다.

초기 메일 조회 기간은 최근 7일로 한다. 오늘 일정과 관련된 메일, Outlook의 중요 표시·미확인 메일을 확인 대상으로 삼는다. 관련성 판단과 중요 표시·미확인 조건의 구체적인 필터 조합은 구현 설계에서 검토한다. 요약할 정보의 범위와 요약 구현 방식도 추가로 정한다. 회사 메일 내용을 외부 요약 서비스에 전달할 경우의 사용자 동의와 조직 허용 여부는 구현 전에 확인한다.

OneNote는 휴대폰에서 차량에 가져올 노트를 선택하고 차량에서 조회하는 기능을 구현한다. 음성으로 입력한 새 메모는 내용을 확인한 뒤 개인 OneNote의 전용 섹션에 저장한다. 기존 노트를 수정하는 기능은 이번 범위에 포함하지 않는다. 저장 실패 처리는 추가로 정한다.

음성 입력은 Pleos SpeechToText SDK로 텍스트를 받아 OneNote의 새 페이지로 저장하는 방식을 검토한다. 이 SDK는 음성을 텍스트로 바꾸며, 업무 명령의 이해와 실행까지 자동으로 제공하지는 않는다. 공식 문서상 온디바이스 모드는 앱 등록 없이 이용할 수 있고, 서버 기반 모드는 별도 등록이 필요하므로 에뮬레이터에서 사용 가능한 경로를 확인한다. [SpeechToText SDK](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro)

OneNote 공식 개요는 사용자 위임 인증을 사용하도록 안내한다. 페이지 목록 API에는 회사 계정과 개인 Microsoft 계정의 권한이 각각 안내되어 있다. [OneNote 개요](https://learn.microsoft.com/en-us/graph/integrate-with-onenote), [페이지 조회](https://learn.microsoft.com/en-us/graph/api/onenote-list-pages?view=graph-rest-1.0)

새 페이지 저장은 Microsoft Graph의 페이지 생성 API로 검증한다. 읽기와 새 페이지 생성에 필요한 사용자 위임 권한을 함께 확인하고, 조직 계정에서는 관리자의 동의 정책도 확인한다. [페이지 생성](https://learn.microsoft.com/en-us/graph/api/onenote-post-pages?view=graph-rest-1.0)

## 8 음악 이용

최초 목표는 YouTube Music 계정의 재생목록을 불러오고 차량 스피커로 실제 재생하며 조작하는 것이다. 사용자는 공식적인 차량 직접 연동 경로를 확보하지 못하면 휴대폰 YouTube Music 공식 앱과 차량 오디오 연결을 이용하는 방식도 허용했다.

따라서 두 경로를 구분한다. 차량 직접 연동은 개인 목록 조회와 실제 재생·조작의 공식 지원을 모두 확인한 경우에만 구현 범위로 확정한다. 휴대폰 경로에서는 공식 앱이 계정과 재생을 담당하고 차량 오디오로 소리를 전달한다. 이 경로를 선택했다고 해서 SHIFT 화면에서 재생목록 조회나 조작까지 가능한 것으로 간주하지 않는다.

계정 연결, 개인 재생목록 조회, 차량에서의 재생, 차량 화면에서의 조작을 각각 검증한다. YouTube Data API의 재생목록 조회 지원만으로 YouTube Music의 라이브러리와 차량 재생 전체가 지원된다고 가정하지 않는다.

공식 YouTube Music 안내에는 일부 차량과 서비스의 연동 사례가 있지만, 그것이 SHIFT나 Pleos 에뮬레이터에서 사용할 수 있는 공개 연동 수단을 의미하지는 않는다. YouTube API를 이용하는 자체 플레이어에는 음성 분리 및 백그라운드 재생 제한도 있다. [공식 이용 기기 안내](https://support.google.com/youtubemusic/answer/9231765?hl=en), [재생목록 API](https://developers.google.com/youtube/v3/docs/playlists/list), [YouTube 개발 정책](https://developers.google.com/youtube/terms/developer-policies)

시연에서는 실제 차량 오디오 연결과 Pleos 에뮬레이터의 오디오 출력을 구분한다. 휴대폰에서 음악을 재생하고 PC 스피커로 소리를 냈다는 사실만으로 에뮬레이터 내부의 음악 연동이 구현되었다고 제시하지 않는다. 휴대폰 및 차량 오디오 경로의 연결 해제와 남는 기록도 별도로 확인한다.

## 9 차량에서의 이용 방식

SHIFT의 개인화는 업무와 개인 서비스의 이용 환경을 현재 차량에 연결하는 것을 중심으로 한다. 공조·풍량·조명, 좌석 위치와 같은 물리적 차량 설정의 저장·자동 복원은 출품 범위에 포함하지 않는다.

차량특화성은 차량의 내비게이션과 업무 목적지 연결, 차량에서의 음성 메모, 운전자 교체에 맞춘 개인 환경 전환으로 설명한다. SDK를 많이 사용하는 것 자체를 목표로 삼지 않는다.

NaviHelper를 이용해 확인된 목적지를 차량 내비게이션에 전달한다. 선호하는 모든 내비게이션 앱을 자유롭게 전환하는 기능은 이 SDK의 지원으로 단정하지 않는다. [NaviHelper SDK](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)

공식 목적지 요청 예시는 위도·경도와 장소 정보를 전달한다. 메일에서 주소를 추출하는 과정과 그 주소의 좌표를 확인하는 과정을 구분하고, 좌표 검색 경로는 구현 단계에서 선정한다. 경로 요청 호출만으로 안내가 완료되었다고 표시하지 않고 SDK의 완료·오류 이벤트를 확인한다. [목적지 요청과 결과 확인](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations)

인증과 업무 준비, 긴 원문 조회, 노트 선택, 이용 종료는 우선 주차 상태에서의 흐름으로 설계한다. 주행 중에는 플랫폼이 허용하는 기능만 노출한다. 음성으로 조작한다는 이유만으로 모든 기능이 허용된다고 가정하지 않는다. 앱 카테고리와 `CarUxRestrictions`에 따른 제한을 실제 에뮬레이터에서 확인한다. [주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline), [지역별 주행 규제](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)

SHIFT의 주목적은 업무 지원이므로 Business 카테고리와 그 제약을 검토한다. 음악 기능을 포함했다는 이유로 앱 전체가 Music/Audio의 주행 중 허용 범위를 자동으로 갖는다고 판단하지 않는다. [앱 카테고리](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category)

## 10 사내 차량 관리 확장 범위

차량 배정·예약·대여·차량 반납과 운영 현황 관리는 확장으로 남긴다. 초기 SHIFT는 이미 배정받은 차량에서 개인 업무 세션을 시작하고 종료한다. 차량 문 개방·키 발급도 초기 범위에 포함하지 않는다.

확장 후보는 회사·차량 등록 관리자 화면, 직원 초대·권한 관리, 차량 목록과 예약·취소·연장, 차량 이용 이력 및 인계 메모다. 이전에 정한 자동 확정과 중복 방지 정책은 확장 검토 자료로 보존하며 현재 필수 요구사항으로 취급하지 않는다.

초기 구현에 필요한 회사·차량 식별정보는 시험 환경에 사전 설정한다. 회사 계정 로그인만으로 모든 현대차나 차량 배정 정보가 자동 조회된다고 가정하지 않는다. 실제 차량 이용 권한 확인과 SHIFT의 개인 업무 인증은 역할을 구분한다.

## 11 개인 정보와 세션 종료

다음 탑승을 위해 서비스 연결 상태와 선택한 노트 등 최소 설정만 계정에 보관한다. 사용자는 언제든 서비스 연결을 해제할 수 있다. 차량 이용 종료 시에는 그 차량에 부여한 개인 세션의 접근과 앱 내 개인 데이터를 정리한다. 계정에 설정을 남기는 것과 차량에 개인 업무 내용을 남기는 것을 구분한다.

정리 대상은 SHIFT가 관리하는 토큰, 세션, 캐시, 개인 화면과 저장 자료를 기준으로 정의한다. 차량 운영체제, 기본 내비게이션, 다른 음악 앱의 모든 기록까지 삭제된다고 표시하지 않는다. 타 앱이나 플랫폼에 전달한 정보는 해당 기능의 지원 여부를 별도로 확인한다.

개인 메일, OneNote 내용과 음악 이용 내용은 회사 관리자에게 공개하지 않는다. 초기 구현에 예약·이용 이력·인계 메모를 수집하는 관리 화면은 두지 않는다. 향후 차량 관리 기능을 확장하면 운영 기록과 개인 업무 내용을 구분하는 원칙을 유지한다.

종료를 잊었을 때를 위해 휴대폰 원격 종료와 일정 시간 비활동 후 자동 잠금을 제공한다. 잠금은 업무 정보 접근을 막으며 차량 제어나 기존 내비게이션을 중단하지 않는다. 비활동 판정과 잠금 시간, 재인증의 상세 동작은 시험 후 정한다.

세션·시험 기록의 보관 기간과 실제 실증 규모는 시험·실증 협의 후 정한다. 연결 해제와 통신 단절 시 정리 재시도는 구현 설계에서 검토한다. 물리적 차량 설정을 복원하는 동작은 포함하지 않는다.

Pleos는 운전자 교체 시 로그아웃과 계정 전환, 토큰의 안전한 저장, 개인정보 최소 수집을 안내한다. [계정과 개인정보 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/security-privacy)

## 12 개발 구성

| 구성 요소 | 확정된 역할 | 미정 항목 |
| --- | --- | --- |
| 차량 앱 | Kotlin·Jetpack Compose 기반 Pleos Connect Android 앱 | SDK와 Compose·빌드 도구의 호환 버전 |
| 휴대폰 모바일 웹 | TypeScript·React·Next.js 기반 계정 연결, 노트 선택, QR 승인과 원격 종료 | 실제 배포 환경 |
| 공통 API | Next.js Route Handlers의 Node.js 서버에서 회사·차량 식별정보, 인증과 개인 세션을 연결 | 세션 상세 설계와 배포 환경 |
| 데이터 저장소 | PostgreSQL에 최소 계정 설정과 세션 상태 저장 | DB 운영 환경과 버전 |
| 업무 연결 | 회사·학교 Microsoft 365 시험 계정과 OneNote를 연결 | 조직 동의 정책, 권한, 실제 동작 검증 |
| 음악 연결 | YouTube Music의 실제 이용 경로를 연결 | 공식 직접 연동 지원, 휴대폰 공식 앱·차량 오디오 경로 |

사용자가 기술 선정을 위임해 위 구성을 기본 스택으로 정했다. Android는 공식 권장 UI 도구인 Compose를 사용하고, 웹과 API는 같은 TypeScript 프로젝트에서 개발한다. 세부 버전은 Pleos 샘플 빌드와 Microsoft 인증을 검증한 뒤 고정한다. [Compose](https://developer.android.com/compose), [Pleos 시작 가이드](https://document.pleos.ai/en/docs/pleos-only/getting-started), [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)

Microsoft 인증은 공식 MSAL Node와 Microsoft Graph를 사용하는 서버 연동을 기본으로 한다. 등록된 조직과 사용자 동의를 확인하고, 차량에는 해당 SHIFT 세션에 필요한 접근만 부여한다. 서버용 비밀값을 차량 앱이나 브라우저에 넣지 않는다. [MSAL Node](https://learn.microsoft.com/en-us/entra/msal/javascript/node/initialize-confidential-client-application)

배포 플랫폼과 DB 운영 서비스, AI 요약 모델·제공자는 아직 선정하지 않았다. 배포 계정, Microsoft 앱 등록과 APK 릴리스 서명 키는 사용자가 소유·관리하고 친구에게 필요한 협업 권한을 부여한다. 실제 계정 개설·권한 설정·키 발급은 아직 수행하지 않았다.

GitHub 작업은 기능별 브랜치에서 진행하고 PR을 만든 뒤 상대방 확인 후 main에 병합한다. [제작·협업 계획](DELIVERY_PLAN.md)에 초기 기술 검증과 변경 검토 방법을 정리한다.

현재 로컬 환경에서 Android Studio, Android SDK, 에뮬레이터 실행 파일과 Android Studio 내장 Java의 존재를 확인했다. Node.js와 npm도 사용할 수 있다. 확인된 AVD는 일반 Pixel 기기이며, Pleos Connect 에뮬레이터 설치·실행과 SDK 앱 빌드는 아직 확인하지 않았다. 설치 파일의 존재를 실제 차량 앱 구동 검증으로 간주하지 않는다.

공모전은 공개된 Pleos SDK와 API 범위에서 개발하며, 미공개 SDK와 Pleos LLM SDK 제공을 전제하지 않는다. 차량 마이크의 외부 음성 인식 서비스 전송 대신 공식 SpeechToText SDK를 사용한다. [공식 개발 범위](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)

## 13 시연 시나리오

직원 A가 이미 배정받은 차량에 탑승하고 인증한다. 오늘 방문 업무와 참고 노트를 확인하고 목적지를 내비게이션에 전달한다. 방문 후 메모를 확인해 OneNote에 저장하고 개인 세션을 종료한다. 직원 B가 같은 차량에서 인증하면 B의 환경이 표시된다. 음악은 기존에 확정한 보조 기능으로 지원 경로를 검증한다.

1차 영상은 PC에 차량·휴대폰 클릭형 시안을 나란히 띄워 녹화한다. 관리자 등록, 예약·취소와 차량 반납 화면은 넣지 않는다. 1차 클릭형 화면과 PT의 실제 계정·SDK 연동을 구분해 표시한다. 실제 고객 정보 대신 시험 데이터를 사용한다.

시연에서는 다음 결과를 화면 전환과 함께 확인한다. 계정 A의 일정·메일 근거가 목적지 제안에 연결되는지, 사용자가 확정한 장소가 실제 내비게이션에 전달되는지, 음성으로 작성한 메모가 실제 OneNote에서 조회되는지, 계정 B로 전환한 뒤 A의 화면과 개인 데이터에 접근할 수 없는지를 확인한다. 음악은 사용한 재생 경로를 화면과 설명에 명시한다.

## 14 검증 계획

이번 자체 검증에서는 방문 준비 시간의 기존 방식 대비 비교, 실제 OneNote 저장 결과, A/B 전환 후 이전 정보 접근 차단을 모두 확인한다. 자세한 측정 구간과 성공 판정은 [제작·검증 계획](DELIVERY_PLAN.md)에 따른다. 수치 목표는 시험 후 정하며 아래 기술 동작도 함께 확인한다.

- 최초 연결 이후 반복 탑승에서 필요한 인증과 설정 단계 수
- 인증 후 업무·노트·음악 환경을 사용할 수 있을 때까지의 시간과 연동별 성공 여부
- 일정과 메일에서 제안한 목적지의 정확성 및 확인 과정
- 실제 OneNote 조회 또는 저장 결과
- 실제 음악 계정의 목록 조회와 차량 재생 및 조작 결과
- A의 세션 종료 후 B 화면에 A의 개인 정보가 노출되는지
- 계정 연결 실패, 통신 단절과 세션 만료 처리

다음 위험은 출품 설명과 개발 검증에서 우선 다룬다.

| 검증할 위험 | 기획에서의 대응 | 확인할 결과 |
| --- | --- | --- |
| 업무 정보를 나열하는 데 그치는 경우 | 고객사 방문 전후의 하나의 업무 흐름으로 시연 | 목적지 전달과 방문 후 메모가 실제로 이어지는지 |
| 요약이나 주소 추출 오류 | 원본 근거와 장소 후보를 표시하고 실행 전 확인 | 불확실한 장소를 자동 확정하지 않는지 |
| Microsoft 365 조직 동의 거부 | 시험 계정과 조직 정책을 실제 연결 초기에 확인 | 허용된 권한만으로 조회·저장이 가능한지 |
| YouTube Music 직접 연동 경로 미확보 | 승인된 휴대폰 공식 앱 경로를 별도로 검증 | 가능한 재생·조작 범위를 사실대로 제시하는지 |
| 주행 중 업무 화면 사용 제한 | 주차 중심 흐름과 제한 상태별 화면을 설계 | 플랫폼이 금지한 화면·입력이 노출되지 않는지 |
| 교대 시 이전 직원 정보 노출 | 차량 세션 종료와 앱 내 데이터 정리를 검증 | B가 A의 데이터에 화면이나 서버를 통해 접근할 수 없는지 |

## 15 사내 도입과 확장 방향

현대자동차의 사내 공용차에서 업무 연결과 개인 세션 전환을 제공하는 내부 서비스로 제안하고, 검증한 뒤 외부 기업으로의 확대를 검토한다. 독립 월 구독 사업은 전제하지 않는다.

직원의 업무 정보 재입력과 방문 후 메모 정리 부담을 줄이고, 공용차의 직원 교대에 맞춰 개인 정보를 분리하는 가치를 제시한다. 예약·배정 등 사내 차량 관리 기능은 이 가치를 확인한 뒤 추가할 수 있는 확장이다.

도입 경로는 사내 공용차 이용 조직에서의 소규모 실증, 운영 정책 조정, 적용 조직 확대의 순서로 제안한다. 실제 실증 규모는 시제품 시험과 실증 협의 후 정하기로 했다. 실증 부서, 접촉 창구와 운영 예산도 미정이다.

확장 대상은 외부 기업의 공용차이며, Microsoft 연동 시험과 현대자동차의 실제 사내 시스템 연계를 구분한다. 초기 시험 계정의 연동 성공만으로 현대자동차 전사 시스템에서 사용할 수 있다고 판단하지 않는다. 예상 MAU와 유지율은 실증에 근거한 목표를 세우며, 검증 전에는 실적으로 제시하지 않는다.

평가에 제시할 사용성·지속 이용 지표는 아래와 같이 정의한다. 실제 수집 항목과 동의 방식은 개발 착수 때 정하고, 수치 목표는 시험·실증 후 확정한다.

| 지표 | 측정할 내용 |
| --- | --- |
| 월간 활성 이용자 | 한 달 동안 실제 차량 세션에서 일정 확인·목적지 전송·노트 이용 등 핵심 기능을 사용한 직원 수 |
| 4주 재이용 | 첫 이용 후 4주 이내 핵심 차량 업무 기능을 다시 사용한 직원의 비율. 공용차를 다시 이용할 기회가 있었는지도 함께 확인 |
| 방문 준비 시간 | 차량 인증부터 방문 정보를 확인하고 목적지를 전달하기까지의 시간 |
| 방문 후 기록 | 음성 메모를 확인한 뒤 실제 OneNote 저장이 완료되었는지 |
| 교대 시 정보 분리 | 다음 직원의 화면과 세션에서 이전 직원의 개인 정보에 접근할 수 없는지 |

초기 이용자 확보는 사내 공용차 이용 안내와 회사 초대 링크로 제안한다. SHIFT 인증부터 실제 방문 업무 이용까지 이어지는 비율과 반복 이용 이유를 확인해 적용 부서를 늘리는 근거로 삼는다.

개인 음악과 QR 연결만으로 독창성을 설명하지 않는다. YouTube Music 공식 안내에는 Waymo에서 모바일 앱이나 차량 QR로 계정을 연결하는 사례도 있다. SHIFT의 차별점은 영업·외근 직원의 일정·메일·노트와 차량 이용 권한, 교대 시 세션 정리를 하나의 흐름으로 설계하는 데 두며, 해당 조합의 사용자 가치는 실증으로 확인한다. [YouTube Music의 차량 연동 사례](https://support.google.com/youtubemusic/answer/9231765?hl=en)
